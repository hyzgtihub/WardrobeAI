# 衣序 YISU｜Gate A 高保真 UI 设计规格

日期：2026-08-13  
状态：方案 A 已确认，待用户复核书面规格后启动 Figma 实施  
设计文件：`衣序 YISU｜Gate A 原型与 UI 设计｜2026-08-10`

## 1. 阶段目标

在已验收的 Gate A 低保真页面和可点击原型基础上，完成 Light Mode 高保真 UI、通用组件体系、关键状态和完整可点击原型，使设计达到 SwiftUI 可实现、可标注、可验收的交付状态。

## 2. 已确认实施方式

采用方案 A：分批设计、逐批验收。

- 先确认视觉方向，再固化 Foundations 与组件。
- 账户、衣橱浏览、衣物管理分批制作和确认。
- 每一批通过后再进入下一批；已确认内容仅处理明确缺陷或已批准的范围变更。
- 第一轮只制作 P01 登录、P05 衣橱首页、P09 衣物详情三张视觉方向样稿，不直接铺开全部页面。

## 3. 范围基线

### 3.1 包含

- 邮箱密码登录、注册、忘记密码与邮箱重置链接流程。
- 登录和注册协议勾选、服务条款、隐私政策。
- 默认角色“我”的初始化和展示。
- 衣橱首页、分类筛选、搜索及三栏底部导航。
- 选择照片、确认照片、添加衣物、详情、编辑、重新上传照片和删除确认。
- 搭配暂未开放页、我的基础页。
- 正常、加载、空白、无结果、校验失败、禁用、保存中、删除失败、网络异常与重试状态。

### 3.2 不包含

- 微信、手机号、Sign in with Apple。
- 宝宝或其他角色以及角色切换。
- AI 搭配、正式搭配功能、社区、支付。
- Dark Mode。

## 4. 视觉原则

- 品牌气质：自然、有序、温和、简洁。
- 平台基线：iOS 原生体验，使用 SF Pro 系统字体和安全区域规则。
- 色彩：以现有鼠尾草绿色系与暖白中性色为基础，功能色只表达状态，不承担装饰。
- 层级：主操作、次操作、危险操作有稳定且可复用的视觉优先级。
- 内容优先：衣物图片和名称是浏览页面的主要视觉信息；装饰不干扰识别。
- 可实现性：颜色、字体、间距、圆角和状态必须能映射为 SwiftUI Design Token 或组件属性。

## 5. 实施批次与确认门

### Gate B1：视觉方向

制作 P01 登录、P05 衣橱首页、P09 衣物详情高保真样稿，并给出页面放在一起时的视觉一致性说明。

通过条件：

- 三个页面的颜色、字体、圆角、图标、图片和操作层级一致。
- 品牌主色不降低文字和控件可读性。
- 衣橱首页的内容密度、卡片比例和导航样式获得用户确认。
- 用户明确确认视觉方向后，方可进入 B2。

### Gate B2：Foundations 与组件

固化颜色变量、字体样式、间距、圆角、阴影、栅格、安全区域、图标规则和图片规则；升级 Button、Form Field、Category Chip、Garment Card、Navigation Bar、Bottom Tab Bar、Checkbox、Selection Row、Tag、Empty State、Error State、Loading Skeleton、Toast、Alert、Action Sheet 与图片上传组件。

通过条件：

- 页面元素使用变量和组件实例，不出现无意的游离样式。
- 每个组件覆盖实际需要的默认、按下、选中、禁用、加载、错误或聚焦状态。
- 关键点击区域原则上不小于 44×44 pt。
- 命名可直接对应 SwiftUI 实现。

### Gate B3：账户与协议页面

完成登录、注册、忘记密码、邮件已发送、设置新密码、服务条款、隐私政策和默认角色初始化状态。

通过条件：

- 协议默认勾选，协议文字可单独点击；取消勾选后主按钮禁用。
- 忘记密码为邮箱重置链接方案。
- 表单校验、提交中、认证失败和服务失败表现清楚。
- 键盘不遮挡当前输入框或关键操作。

### Gate B4：衣橱浏览页面

完成衣橱首页各状态、分类选中、搜索及无结果、搭配暂未开放、我的基础页和三栏底部导航。

通过条件：

- 分类完整包含全部、上衣、裤子、外套、裙子、鞋子、配饰、其他。
- 卡片名称和第二行信息不被遮挡；长文字规则一致。
- 衣橱默认选中，当前分类和当前导航状态明确。
- 加载、空白、有数据、筛选结果和失败状态完整。

### Gate B5：衣物录入与管理页面

完成选择与确认照片、添加衣物、详情、编辑、重新上传照片、字段选择面板、删除确认和删除失败。

通过条件：

- 重要信息为图片、名称、分类、季节、收纳位置、备注；其他字段置于次要信息层。
- 字段顺序、必填性、选项和格式与 PRD 一致。
- 季节全选显示“四季”；价格为非必填、人民币元、数值不小于 0、最多两位小数。
- 收纳位置按层级选择，且仅该字段的每一级均非必填。
- 编辑取消返回衣物详情；照片选择取消返回原始入口。
- 编辑页面支持重新上传照片。

### Gate B6：完整原型与开发交付

连接账户、初始化、衣橱浏览、添加、详情、编辑、删除、密码重置和协议流程，完成状态、无障碍、开发标注与资源检查。

通过条件：

- 所有主要入口可达，无失效目标节点或无法退出的页面。
- 返回、取消、保存和删除后的目标符合已确认流程。
- 页面无文字遮挡、内容越界、异常 Home Indicator 或安全区域问题。
- Figma Foundations、组件、页面、状态、资源和 SwiftUI Token 对照齐全。
- 用户完成最终视觉验收后更新项目交付管理包并归档。

## 6. 质量检查方法

- 结构审计：核对页面、组件实例、变量引用、页面命名和原型目标。
- 视觉审计：逐页检查对齐、间距、文字截断、对比度、图片裁切和安全区域。
- 状态审计：按需求清单核对正常、加载、空白、错误、无结果、禁用、保存中和删除失败。
- 流程审计：从登录开始完整走查添加、搜索、详情、编辑、换图、删除和密码重置流程。
- 开发交付审计：核对 SwiftUI Token、组件状态、尺寸标注和导出资源。

## 7. 周期与变更规则

- 预计周期：10～14 个工作日，不含用户确认等待时间。
- 计划按 B1 至 B6 顺序推进；每个确认门只记录一次正式通过结论。
- 新需求先评估对范围、周期和已确认页面的影响，再写入项目交付管理包；未经确认不直接混入当前批次。
- 本阶段所有项目周期调整继续以 `衣序YISU-项目交付管理包-iOS原生基线-20260722.xlsx` 为唯一周期管理基线。

## 8. 启动条件

用户复核并确认本书面规格后，开始 Gate B1，在现有 Figma 文件中制作 P01、P05、P09 三张视觉方向样稿；在 B1 获得确认之前，不批量修改其余页面。
