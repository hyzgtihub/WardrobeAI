# 衣序 P01–P05 Hi-Fi 页面实现规格

## 1. 目标与范围

本轮把已验收的 Figma 高保真页面实现为可交互 SwiftUI 页面：

- P01 登录：Figma `294:5`。
- P02 注册六态：Figma `478:124`。
- P03 初始化衣橱、P04 当前衣橱六态：Figma `480:456`。
- P05 衣橱首页：Figma `294:48`。

采用 UI-first：实现真实输入、校验、状态切换、路由与可测试的本地确定性状态；通过闭包或协议预留服务入口。本轮不接真实认证 API、云同步、数据库或照片上传。P13–P16 不在本轮。

## 2. 视觉与组件来源

- 唯一视觉源为 Gate B1 V3B 与 Gate B3 v1.1 已验收节点。
- 颜色、排版、间距、圆角、阴影和触控尺寸统一使用 `YISUTheme`，页面不得散落私有色值。
- 复用现有 `YISUButton`、`YISUContentStateView`、`YISUCategoryFilter`、`YISUGarmentGrid` 与 `YISUBottomNavigation`。
- 新增最小认证组件：认证背景、认证卡片、文本字段、密码字段、协议复选框；P01 与 P02 共用，不逐页重画。
- P05 使用交付包中的四张透明衣物图片并加入 Asset Catalog；不使用随机图片或占位图代替确认稿资源。

## 3. 页面与状态

### P01 登录

包含品牌标识、标题与副标题、邮箱、密码显示切换、登录按钮、注册、忘记密码、协议复选框和两份协议入口。邮箱格式有效、密码非空且协议已勾选时允许提交。提交只触发注入动作，不伪造服务端成功。

### P02 注册

一个页面通过状态模型承载六态：默认、密码不符合、邮箱已存在、提交中、服务失败、协议未勾选。密码至少 8 位且两次一致；错误同时使用文字、边框或图标表达，不仅依赖颜色。提交中阻止重复操作。

### P03 初始化衣橱与 P04 当前衣橱

使用单一流程状态枚举承载：正在创建、创建失败、创建成功、当前角色、加载中、加载失败。失败态提供重试；成功后进入当前衣橱；当前角色进入 P05。状态组件复用，不创建六个独立页面类型。

### P05 衣橱首页

展示问候、标题、数量、搜索入口、八类筛选、两列衣物网格、三入口底部导航和中央添加按钮。使用四件确认稿衣物示例数据；分类筛选在本地生效。搜索、衣物详情、添加衣物和“我的”通过注入动作或路由枚举暴露，本轮不扩展其目标页面。

## 4. 路由与状态边界

根级路由使用轻量枚举表达 `signIn`、`signUp`、`onboarding`、`wardrobe`，由一个本地 `@State` 或 `@Observable` 会话模型驱动。页面不直接依赖网络或数据库。预览和 UI 测试可用启动参数进入目标页面或指定状态，正式默认入口仍为 P01。

## 5. 无障碍与适配

- 所有独立操作区至少 `44×44pt`。
- 输入框具备可见标签、正确键盘类型、Content Type、提交顺序和错误说明。
- 密码显示按钮、复选框、筛选与底栏必须报告标签及选中状态。
- 使用语义字体并支持 Dynamic Type；键盘弹出时当前字段、错误与主操作可滚动到可见区域。
- 页面遵守安全区；状态不只通过颜色表达。

## 6. 测试与验收

- 单元测试覆盖邮箱、密码、协议、提交许可、P03/P04 状态转换与 P05 分类筛选。
- UI 测试覆盖 P01→P02、P01→P03/P04→P05 的本地可达路径，以及关键禁用/错误/重试状态。
- 现有设计系统测试和登录默认入口 smoke test同步更新，不降低既有覆盖。
- 最终执行完整 `xcodebuild build`、单元测试、UI 测试和 `git diff --check`。
- 验收不批量输出截图；仅在发现视觉或可达性问题时提供证据。

## 7. 交付策略

主代理串行实现，按“认证共享层与 P01 → P02 → P03/P04 → P05”分四阶段，每阶段完成后统一复核一次。只提交本轮文件，保留并排除用户现有的 Xcode Scheme 未提交改动。
