# 衣序衣橱分类浏览与组合筛选设计

## 1. 目标

在现有 P05 衣橱首页内提供快速分类浏览和多维组合筛选，让用户无需文本搜索即可缩小当前衣橱的衣物范围。本周期仅处理已加载到客户端的衣物，不新增服务端查询、收藏或智能集合能力。

## 2. 本期范围

### 包含

- 首页分类浏览：全部、上衣、裤子、连衣裙、外套、鞋履、包袋、配饰、其他。
- 分类数量与筛选结果数量。
- 底部 Sheet 形式的组合筛选。
- 筛选维度：分类、季节、颜色、材质、风格、尺码、收纳位置。
- 首页已生效条件标签、单项移除、筛选状态圆点和一键清空。
- 空结果状态、添加衣物入口、无障碍状态与大字体适配。
- 当前登录会话中的筛选状态保留。

### 不包含

- 文本搜索框、搜索按钮或独立搜索页。
- 品牌、价格、购买日期、场合、图案、评分、穿着次数、洗衣状态筛选。
- 收藏和智能集合。
- 服务端筛选、筛选偏好云同步或设备长期存储。
- 对数据库结构或 Supabase API 的修改。

## 3. 首页信息结构

现有首页右上角搜索按钮删除。标题区下方依次展示：

1. 筛选控制行：左侧为 `line.3.horizontal.decrease` 系统图标按钮；右侧横向展示已生效的非分类条件标签。
2. 分类浏览行：固定顺序展示全部九个分类及数量。
3. 衣物网格或状态视图。

筛选按钮视觉尺寸可以紧凑，但点击区域不得小于 `44×44 pt`。存在任意非分类组合筛选条件时，按钮右上角显示品牌色小圆点；圆点不是唯一状态表达，VoiceOver 同时播报“筛选，已有条件”。只有首页单分类条件时不显示圆点。

已生效的季节、颜色、材质、风格、尺码和收纳位置使用可移除标签展示。标签横向滚动，不强制压缩或截断；每个标签都是原生按钮，朗读为“移除筛选，白色”等。分类不在此处重复展示。

## 4. 分类浏览

分类顺序固定为：

`全部｜上衣｜裤子｜连衣裙｜外套｜鞋履｜包袋｜配饰｜其他`

- 每项展示当前完整衣橱中的数量，而不是被其他筛选条件缩小后的数量。
- 点击单一分类会替换当前分类条件，并保留其他维度条件。
- 点击“全部”清空分类条件，不清除其他筛选。
- 从筛选 Sheet 选择多个分类后，分类栏增加并选中“多分类”聚合状态；分类数量摘要为多分类命中数量。
- 在“多分类”状态点击任一单分类，会用该分类替换多分类条件。
- 分类无结果时仍保留分类栏和筛选控制。

## 5. 筛选 Sheet

筛选面板使用 iOS 底部 Sheet，采用大高度 detent 并显示拖动指示器。顶部固定左侧关闭按钮和居中标题“筛选”，底部固定“重置”和“完成”，中间内容可滚动且不得被底部操作区遮挡。

筛选维度按以下顺序展示：

1. 分类
2. 季节
3. 颜色
4. 材质
5. 风格
6. 尺码
7. 收纳位置

每个维度使用可展开区块；右侧展示当前选择摘要和展开状态。展开后以多选标签展示选项。同一维度内任一选项命中即可，不同维度之间必须同时命中。

Sheet 使用独立草稿状态：

- 打开时从当前已生效条件复制草稿。
- 点击“完成”应用草稿、关闭 Sheet，并立即刷新首页。
- 点击关闭、下滑关闭或系统交互式关闭时放弃草稿，保留打开前的已生效条件。
- “重置”只清空草稿；必须再点击“完成”才清空首页条件。
- 再次打开时始终从当前已生效条件开始。

## 6. 筛选选项来源

- 分类和季节使用应用内固定选项及固定顺序。
- 颜色、材质、风格、尺码和收纳位置从当前已加载衣物中提取、去空、去重。
- 动态维度只显示至少被一件衣物使用的值，自定义录入值自动成为筛选项。
- 去重键先去除首尾空白，再按本地化、不区分英文大小写比较；展示文字保留首个稳定出现的原始写法。
- 每个选项显示完整衣橱中的匹配数量，例如“棉 6”。
- 新增、编辑或删除衣物后重新派生选项和数量。

## 7. 匹配规则

- 分类：衣物分类在已选分类集合中。
- 季节、颜色、材质、风格：衣物数组与该维度选择集合至少有一个规范化值相交。
- 尺码、收纳位置：衣物的规范化单值在该维度选择集合中。
- 同维度为空表示该维度不限制。
- 所有非空维度之间使用“且”。
- 结果保持 `GarmentStore.garments` 的既有顺序，不新增排序方式。
- 规范化只用于比较，不修改或回写衣物数据。

## 8. 状态与生命周期

- 条件保存在衣橱首页所属的会话级状态中。
- 进入衣物详情再返回、添加衣物后返回首页时保留已生效条件。
- 新增、编辑或删除导致结果变化时，以最新衣物数据重新计算结果和选项。
- 退出账号、切换账号或 App 进程重启后恢复“全部、无筛选”。
- 本期不使用 `UserDefaults`、数据库或远端配置持久化筛选条件。

## 9. 空状态

衣橱本身为空时继续使用现有“添加第一件衣物”空状态。

衣橱有数据但筛选结果为空时显示：

- 标题：“没有符合条件的衣物”
- 说明：“可以清空筛选，或添加一件新衣物。”
- 主操作：“清空筛选”
- 次操作：“添加衣物”

清空筛选会同时清除分类和所有组合筛选条件。

## 10. 无障碍与适配

- 所有按钮点击区域至少 `44×44 pt`。
- 图标按钮必须提供中文 `accessibilityLabel`。
- 筛选按钮同时暴露是否存在组合筛选条件，不依赖圆点颜色。
- 多选标签暴露选中状态；折叠区暴露展开状态。
- 条件标签支持大字体，标签文字不得被裁切；横向滚动区域可逐项聚焦。
- Sheet 固定操作区遵守底部安全区，滚动内容不得被遮挡。
- 使用现有语义颜色与字号令牌，验证浅色、深色和高对比状态。

## 11. 技术方案

新增纯值类型 `WardrobeFilter` 表示已生效或草稿条件，包含七个维度的选择集合以及 `isEmpty`、`activeNonCategoryCount` 等派生信息。新增 `WardrobeFilterPolicy` 负责规范化、动态选项派生、计数和本地过滤，保持 UI 与规则解耦。

`WardrobeHomeView` 接收完整 `[Garment]`，而不是只接收缺少筛选字段的 `[GarmentSummary]`。`RootView` 持有会话级 `appliedFilter`，确保进入详情或添加流程再返回时状态不丢失，并在账号退出或变化时重置；首页只持有 Sheet 展示状态。Sheet 自己持有 `draftFilter`，仅通过 `onApply` 提交。`RootView` 继续持有 `GarmentStore`，不会新增数据库请求。

UI 拆分为：

- `WardrobeFilterBar`：筛选按钮、状态圆点和条件标签。
- `WardrobeCategoryBrowser`：分类及数量、多分类聚合状态。
- `WardrobeFilterSheet`：草稿、多维区块、重置与完成。
- `WardrobeFilterPolicy`：纯规则与动态选项。

## 12. 验收标准

1. 首页不再出现搜索按钮或文本搜索入口。
2. 点击筛选按钮打开大高度 Sheet；关闭不应用草稿，完成才应用。
3. 重置后关闭不会改变首页；重置后完成会恢复全部衣物。
4. 同维度多选为“或”，跨维度为“且”。
5. 动态选项来自当前衣橱并正确去重、计数，包含自定义值。
6. 已生效非分类条件显示可移除标签和筛选圆点。
7. 单分类只在分类栏高亮且不显示筛选圆点；多分类显示“多分类”。
8. 点击首页单分类只替换分类条件，其他筛选不变。
9. 进入详情或添加流程后返回，筛选条件仍在；退出账号后清空。
10. 无结果状态可清空筛选或添加衣物。
11. 现有衣物新增、详情编辑、删除和账号流程测试继续通过。
12. VoiceOver、大字体、浅色与深色模式下控件可操作且状态可理解。
